# Final Quality Checklist

Run every applicable check before delivery.

## Interaction gates

- [ ] Recipient-profile inquiry followed the start/skip/stop conditions in SKILL.md: upload timing and user inquiry preferences were respected, sufficient evidence or confirmed profiles were reused, and each unsolicited question addressed a consequential gap or unresolved conflict.
- [ ] A new week, first use, or empty nonessential profile fields did not by themselves trigger an interview; inquiry stopped when sufficient, declined, or unknown to the user.
- [ ] At least one recipient/style source was provided.
- [ ] User-supplied screenshots, annotations, meeting notes, feedback excerpts, or behavioral examples were inventoried with their context and authorship when applicable.
- [ ] Unrelated messages, contact details, avatars, group-member information, and other irrelevant personal data were excluded from the recipient profile.
- [ ] Every reference template without an explicit recipient/peer label was classified as a recipient template; no provenance question was asked solely to distinguish it, and no peer provenance was inferred from filenames, metadata, embedded names, content, or visual style.
- [ ] Any later explicit user correction to template provenance replaced the default classification.
- [ ] In conversational intake, material uncertainties were asked one question at a time with reasons.
- [ ] If questionnaire mode was requested, the questionnaire was compact, adaptive, optional, grounded in concrete behavior, and did not repeat questions already answered by evidence.
- [ ] The user confirmed the summarized goal.
- [ ] The preview included a compact recipient-profile summary with sources, confidence, and material unknowns.
- [ ] The preview explained how the recipient profile changes content priority, evidence depth, and section emphasis.
- [ ] Recipient-profile confirmation material is clearly separate from the proposed weekly-report structure.
- [ ] The style preview included structure, section allocations, representative prose, and figure/table planning.
- [ ] The preview included a language-style map and its representative prose demonstrated the learned sentence density, order, voice, technical depth, and progress/result phrasing.
- [ ] The preview showed how template language was adapted to the plain-language baseline and how necessary technical terms will be explained at first use.
- [ ] For every reviewed paper, the preview showed the selected partition system and language-routing reason, where the routed partition, Journal Impact Factor, and corresponding-author metadata will appear, and whether each field is currently verified.
- [ ] The user had an opportunity to add temporary requirements.
- [ ] The user explicitly confirmed the final preview.

## Authority and style

- [ ] A confirmed recipient profile was reused or a draft was established from current evidence and confirmed.
- [ ] Recipient-profile rules distinguish direct statements from inferences and record source, confidence, scope, and confirmation status.
- [ ] No personality, motive, demographic trait, or sensitive attribute was inferred as part of the recipient profile.
- [ ] No recipient-profile rule was inferred from a peer template.
- [ ] Screenshot and behavioral evidence was recorded as observable behavior first, with alternative explanations considered before proposing a report implication.
- [ ] Response latency, punctuation, emoji use, message length, politeness, or social warmth was not used as evidence of a stable reporting preference without an explicit recipient statement.
- [ ] Low-confidence behavioral hypotheses were not persisted as reusable rules before user confirmation.
- [ ] Stable recipient preferences remain separate from current-report goals and temporary requirements.
- [ ] An internal recipient-fit map links every substantive content unit to a recipient goal or evaluation criterion.
- [ ] Content order, emphasis, evidence depth, risk treatment, and next-step specificity follow the confirmed recipient profile without suppressing decision-relevant evidence.
- [ ] The weekly report does not contain the recipient profile, confidence notes, profile source table, or recipient-fit map.
- [ ] Temporary requirements override every reusable style source.
- [ ] User-described preferences and user-confirmed profile rules derived from feedback or behavioral evidence override recipient and peer templates.
- [ ] Recipient template overrides peer template.
- [ ] Multiple unlabeled templates remain at the same recipient-template authority level; conflicts were clarified or disclosed rather than resolved by silently demoting one to peer status.
- [ ] The confirmed report style profile was reused or updated for a stated reason.
- [ ] One-week temporary requirements were not persisted as permanent preferences without consent.
- [ ] Template-derived identity and assignment values were not treated as reusable style information.
- [ ] Reporter, presenter, respondent, and author values came from current inputs or use the allowed `xxx` default; no old template value was reused.
- [ ] Missing project/client/topic and other assignment-specific values were clarified or remain explicit placeholders.
- [ ] The document title and every used heading level were inspected and implemented as distinct typography roles rather than flattened into one style.
- [ ] Each heading level matches the applicable template in font, size, weight, color, alignment, numbering, indentation, spacing, and keep/page-break behavior.
- [ ] Any heading level absent from the template was derived from neighboring levels, remains visibly hierarchical, and was disclosed in the preview.
- [ ] Figure-caption and table-title/caption typography follows applicable template evidence; only a missing-template fallback uses one typographic size step smaller than body text.
- [ ] Formula text and equation numbers follow the confirmed template or user instruction; when neither establishes a size, both use the same point size as body text.
- [ ] Body-paragraph line spacing was learned from multiple representative template paragraphs and records its mode/value, not estimated only by appearance.
- [ ] Ordinary prose, list text, and table-cell text use separate spacing rules when the template consistently distinguishes them; isolated local overrides were not generalized.
- [ ] Any missing-template fallback for body line spacing was disclosed in the preview.
- [ ] Recipient-facing language style was learned independently from typography and paragraph spacing, using representative passages rather than one isolated sentence.
- [ ] Sentence length, information density, conclusion/process order, voice, terminology density, status verbs, comparison phrasing, and failure/next-step phrasing follow the highest-authority style source.
- [ ] Template language traits were applied on top of the plain-language baseline; jargon, internal shorthand, buzzwords, opaque abstractions, and translation-like phrasing were not copied merely because they appear in a template.
- [ ] The text is written for a smart reader with no assumed topic background and makes the core point and logic understandable on first read.
- [ ] Each sentence or tightly connected sentence group carries one main idea, with concrete subjects, verbs, and explicit cause-and-effect links where needed.
- [ ] Necessary technical terms are retained for accuracy or traceability and explained in plain language at first use; unnecessary specialist terms were replaced.

## Evidence

- [ ] Every consequential number and claim maps to the internal evidence ledger.
- [ ] Paper claims match the supplied paper and include source locations when available.
- [ ] Each reviewed paper includes necessary formulas, experimental settings with a dataset or case-study introduction, and concrete experimental results by default; any inapplicable item or consequential source gap was disclosed in the confirmed preview.
- [ ] Selected formulas are necessary to the paper discussion, match the source, explain key symbols and meaning, and use editable equations where supported with the confirmed font size and numbering.
- [ ] Dataset source, task/type, relevant scale, splits/protocol, baselines, metrics, and consequential settings are described when provided by the paper; missing details or datasets were not fabricated.
- [ ] Central results retain their metric, value/unit, dataset/scenario, and comparison basis; relevant ablation, negative, or mixed findings are not replaced by vague claims of improvement.
- [ ] The paper's experimental or simulation results are clearly attributed and are not presented as the user's own work; settings and scores from different experiments were not conflated.
- [ ] Every paper title in the report uses the exact English original title without a translated title.
- [ ] Each paper title is immediately followed by one parenthetical block in the fixed order `英文论文题目（期刊名称；年份；最新新锐分区；影响因子；通讯作者；国家单位）`; the English route retains JCR in the partition field and uses the same field order.
- [ ] The six metadata fields are semicolon-separated; publication year, partition edition and JIF year are distinguished, country/institution uses `国家—单位`, and multiple authors remain mapped to their affiliations.
- [ ] No metadata field was moved to or repeated in a separate paragraph or standalone “期刊信息” line; natural wrapping did not cause text to be shrunk to fit a single physical line.
- [ ] DOI values remain internal and do not appear in the recipient-facing weekly report.
- [ ] The partition system follows the confirmed deliverable language: Chinese template plus Chinese body uses the latest 新锐分区; English template plus English body uses the latest JCR quartile; mixed or ambiguous language was explicitly clarified.
- [ ] 新锐分区 is labeled as the independent 新锐学术 system and is never described as a Chinese Academy of Sciences partition.
- [ ] Every Chinese-route paper includes the latest verifiable 新锐分区 with its edition/year, category, zone, and applicable status, or an explicit unresolved marker and limitation.
- [ ] Every English-route paper includes the latest verifiable JCR quartile with its JCR year and every applicable Web of Science category, or an explicit unresolved marker and limitation.
- [ ] Every reviewed paper includes the latest verifiable Journal Impact Factor with its JCR/JIF year, or an explicit unresolved marker and limitation.
- [ ] The routed partition and Journal Impact Factor were checked during the current run; an older weekly report was not treated as current evidence.
- [ ] Official sources were preferred; any secondary-source value is labeled with its source, retrieval date, and verification limitation.
- [ ] CiteScore, SJR, an old CAS partition, an unrelated ranking, or a guessed quartile was not substituted for the routed partition metric or Journal Impact Factor.
- [ ] Every corresponding author was identified from explicit correspondence evidence; multiple corresponding authors were all retained.
- [ ] Each corresponding author's country and institution map to an explicitly linked paper affiliation, not a name-based inference.
- [ ] University affiliations show only the university name; school, department, faculty, institute, center, laboratory, and address subdivisions were removed.
- [ ] Non-university affiliations retain the top-level organization, and unresolved author/affiliation fields were not guessed.
- [ ] Completed, ongoing, blocked, and planned work are distinct.
- [ ] Inferences and uncertainties use appropriately qualified language.
- [ ] Evidence uncertainty was handled by narrowing the allowed statement, not by inserting audit-style prose into the weekly report.
- [ ] The report does not list missing thresholds, random seeds, repeated-run statistics, unfinished planned epochs, unavailable baselines, or similar gaps merely to explain what cannot be concluded or claimed.
- [ ] The report contains no routine meta-phrases such as “不能据此判断……”“不能声称……” or “由于未提供……因此只能……”.
- [ ] Current progress is stated directly at the strongest supported level; rejected stronger claims remain only in the internal evidence ledger.
- [ ] Any future evidence-gathering work is written as a concise next action only when supported by current materials or a confirmed plan.
- [ ] Simplification changed wording and structure without deleting conditions that materially change the meaning of the result.
- [ ] The report does not narrate the private drafting process, search process, structural planning, or step-by-step reasoning; it presents the resulting conclusion, evidence chain, and necessary explanation.
- [ ] The report does not narrate table/figure production mechanics such as screenshot reconstruction, cell transcription, embedding, conversion, or axis translation.
- [ ] No citation, metric, experiment setting, cause, or completion status was invented.
- [ ] No person's identity or assignment-specific value was copied from an old template without current evidence.
- [ ] Essential missing information is marked clearly.

## Structure and length

- [ ] Length was matched per meaningful content unit rather than by total report or fixed whole-section length.
- [ ] Papers, experiments/result sets, code/project conclusions, and workplace items were counted as separate units where applicable.
- [ ] Comparable template sections containing multiple units were normalized to a per-unit range.
- [ ] Each section's aggregate allocation scales with its current unit count; a many-item section was not compressed to the same target as a one-item section.
- [ ] Missing template content types used the average of identifiable substantive units, excluding decorative and non-content sections; low-confidence fallbacks were disclosed.
- [ ] Unit lengths were allowed to vary with evidence, complexity, importance, and recipient priorities rather than being made mechanically identical.
- [ ] No section was padded with repetition.
- [ ] Important evidence was not deleted merely to match template length.

## Figures and tables

- [ ] Every non-redundant supplied figure and result table is included unless the user authorized otherwise.
- [ ] Every detected table screenshot without an equivalent native/editable table was shown to the user as a reconstruction choice before drafting.
- [ ] When a genuine native/editable table contains the same data as a screenshot, the native table is used and the duplicate screenshot is absent from the report unless the user explicitly requested both.
- [ ] Reconstructed tables were verified cell by cell; no unreadable or cropped value was guessed.
- [ ] The original table screenshot remains in the evidence set; after reconstruction, the report uses the editable table without the duplicate screenshot unless the user explicitly requested both.
- [ ] Charts with axes use the report-body language for axis titles and textual category labels.
- [ ] Axis translations were made on a derivative; the original image was not overwritten.
- [ ] Translated chart derivatives preserve data, scale, numeric ticks, units, series, and geometry, with no text covering data-bearing elements.
- [ ] Axes, units, legends, labels, and annotations remain legible.
- [ ] Every figure and table has a caption and nearby analysis.
- [ ] Conclusions do not exceed what the figure or table supports.
- [ ] No appendix was created unless requested or present in an applicable template.

## Format and rendering

- [ ] The output format follows the confirmed choice and priority rules.
- [ ] Layout, typography, colors, spacing, numbering, and recurring elements match the selected template.
- [ ] Rendered level 1, level 2, level 3, and deeper headings remain visually distinct and no heading accidentally uses body-text formatting.
- [ ] Figure captions and table titles/captions have the confirmed size, placement, numbering, and spacing and remain legible.
- [ ] Rendered body paragraphs use the confirmed line-spacing mode/value and paragraph spacing before/after without accidental compression or expansion.
- [ ] The artifact remains editable where possible.
- [ ] The rendered output was visually inspected.
- [ ] There is no clipping, overflow, overlap, unreadable text, or broken table.
- [ ] A final plain-language pass removed unexplained jargon, internal slang, management buzzwords, abstract padding, and stiff translation patterns.

## Delivery and privacy

- [ ] The final weekly report is delivered.
- [ ] The recipient profile is delivered only when first established or updated.
- [ ] The report style profile is delivered only when first established or updated.
- [ ] The evidence ledger is withheld unless requested.
- [ ] After report delivery, the user was told that advisor or manager feedback can be supplied to improve the recipient profile.
- [ ] Feedback-derived profile changes distinguish report-specific corrections from stable preferences and were confirmed by the user before persistence.
- [ ] User templates, preferences, profiles, materials, and reports were not added to the Skill package or uploaded.
